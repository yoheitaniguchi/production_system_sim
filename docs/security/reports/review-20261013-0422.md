## 指摘一覧

### SEC-001（Medium）依存脆弱性ゲートがマージの必須条件から外れた

- カテゴリ：§6.3 依存パッケージの脆弱性
- 該当箇所：`.github/workflows/test.yml`（`dependency-audit`ジョブ）、`security/dependencies.security.test.ts`（旧SEC-006を削除した箇所）
- 根拠：変更前のSEC-006はvitestのテストで、`test`ジョブ（mainのRulesetの必須チェック）の中で実行されていた。変更後は
  `dependency-audit`ジョブに移った。このジョブは検出時に失敗するが、Rulesetの必須チェックは`test`・`a11y`・`e2e-scenario`のままで、
  `dependency-audit`は含まれていない
- 影響：ジョブが失敗してもマージボタンは押せる。「本番依存のhigh/critical 0件を必須化」の担保が、必須チェックから目視確認に下がる。
  DependabotのPRや依存を追加するPRで、脆弱な本番依存を見落としてマージする可能性がある。現時点の本番依存は脆弱性0件のため、
  すぐに実害が出る状態ではない
- 修正案：mainのRulesetの必須チェックに`dependency-audit`を加える（リポジトリ設定。ユーザー作業）。あわせて`CLAUDE.md`の
  「3ジョブ」の記述を更新する。必須にしない場合は、その判断と理由を`docs/process/dod.md`に明記する
- 対応するテスト：`security/ci-workflows.security.test.ts`「GitHub Actionsワークフロー（SEC-001: 依存脆弱性ゲートのCIジョブ）」4件
  （ジョブの存在、pull_requestで起動すること、`continue-on-error`等で失敗を握りつぶしていないこと、スクリプトが検出時に非ゼロ終了すること）。
  いずれも成功
- テスト不能の部分：Rulesetの必須チェックに`dependency-audit`が入っているかは、リポジトリ設定でありリポジトリ内のファイルから読めない。
  Settings → Rules → Rulesets（main）で人が確認する

### SEC-002（Low）test.yml・flaky-check.ymlにトップレベルの`permissions`が無い

- カテゴリ：§6.3 CI・ワークフローの権限（最小権限）
- 該当箇所：`.github/workflows/test.yml`（トップレベル）、`.github/workflows/flaky-check.yml`（トップレベル）
- 根拠：トップレベルの`permissions`が無いため、`dependency-audit`・`a11y`・`e2e-scenario`・flaky-checkの各ジョブはリポジトリ既定の
  トークン権限に従う。既定が「Read and write」なら`contents: write`が付く。リポジトリ設定は確認できないため未確認。
  `a11y`・`e2e-scenario`・flaky-checkについては、本差分以前からの状態
- 影響：`npm ci`でサードパーティのinstallスクリプトが動くジョブに、不要な書き込み権限が付く可能性がある。pull_request（フォーク・
  Dependabot）ではトークンが読み取り専用になるため、影響はpush(main)・workflow_dispatch・scheduleに限られる
- 修正案（承認待ち）：

  ```diff
  # .github/workflows/test.yml（on: ブロックの直後。testジョブのジョブ単位の contents: write はそのまま優先される）
  +permissions:
  +  contents: read
  +
   jobs:

  # .github/workflows/flaky-check.yml（同様）
  +permissions:
  +  contents: read
  +
   jobs:
  ```

  あわせて、リポジトリ設定（Settings → Actions → General → Workflow permissions）を「Read repository contents」にすることを推奨する
- 対応するテスト：`security/ci-workflows.security.test.ts`「GitHub Actionsワークフロー（SEC-002: トップレベルpermissionsの明示）」5件。
  `test.yml`・`flaky-check.yml`の2件が失敗（指摘の再現）、他3件は成功

### SEC-004（Info）CodeQLのActionをタグ参照している

## 該当なしとした観点と理由

- §6.1 コードレベル（入力検証・XSS・JSON入出力・BOM再帰・エラー処理など）：差分に`src/`の変更が無い
- §6.2 E2Eレベル：画面・挙動の変更が無い
- 秘密情報の扱い：追加したワークフローは`secrets.*`を参照しておらず、`pull_request_target`も使っていない
- スクリプトインジェクション：`${{ github.event.* }}`は`if:`式の中だけで使い、`run:`のシェルには渡していない
- pr-preview.ymlのDependabot除外条件（`github.event.pull_request.user.login != 'dependabot[bot]'`）：`[bot]`付きのログイン名は
  GitHubが予約しており人が名乗れないため、抜け道は無い。PRの作成者で判定するため、人がDependabotのPRに追加pushした場合や
  closedイベントでも一貫してスキップされる
- DependabotのPRでの`test`ジョブ：`scripts/aggregate-test-results.mjs`がpull_requestトリガーではdataブランチへの書き込みを
  スキップするため、書き込みは起きない
- 依存パッケージの追加・変更：`package.json`・`package-lock.json`に差分が無い
- `dependabot.yml`：自動マージの設定は無く、RulesetとDoDによる人の確認を経てマージする
