---
description: レビュー→指摘対応テスト追加→テスト実行→レポート出力までを自動化するセキュリティレビュー
argument-hint: "[--all]"
---

このリポジトリのセキュリティレビューを、`docs/security/checklist.md`のチェック観点に基づいて実行する。
引数は `$ARGUMENTS` （`--all`が指定されていれば全体、無指定なら差分のみが対象）。

## 1. スコープ決定

- 引数に`--all`が含まれる場合：リポジトリ全体（src・設定ファイル・CI・依存関係）を対象にする
- 引数が無い場合：`git diff main...HEAD --name-only`で変更ファイル一覧を取得し、それらを対象にする
  （変更が無い場合はその旨を報告して終了する）
- 併せて`git rev-parse HEAD`でコミットSHAを取得しておく（レポートのサマリに使う）

## 2. レビュー

`security-reviewer`サブエージェント（Agentツール、`subagent_type: security-reviewer`）を起動し、
上記スコープと`docs/security/checklist.md`を伝えて検査させる。読み取り専用・Bashは監査コマンドのみ
（サブエージェント自身のフックで強制済み）なので、本番コードが変更される心配は無い。

結果を受け取ったら、`docs/security/checklist.md`末尾の「レビュー結果の記録形式」に従って
`docs/security/reports/review-YYYYMMDD-HHMM.md`（現在日時。日本時間である必要は無く、実行時刻を
そのまま使ってよい）を作成する。サマリ（検査範囲・コミットSHA・重大度別件数）と指摘一覧（ID・重大度・
カテゴリ・該当箇所・根拠・影響・修正案）、該当なしとした項目・理由を記載する。

## 3. テスト追加

重大度がInfo以外の指摘それぞれについて、`security-test-writer`サブエージェント
（`subagent_type: security-test-writer`）を起動し、指摘内容（該当箇所・根拠・重大度・カテゴリ）を
渡してテストを追加させる。このサブエージェントはテストファイル以外を編集できない
（フックで強制済み）ため、本番コードが誤って書き換えられることは無い。

- 1指摘ずつ呼び出してもよいし、関連する指摘をまとめて1回で渡してもよい（判断は状況に応じる）
- 返ってきた「対応するテスト（ファイル名・テスト名）」または「テスト不能の理由」を、レポートの
  対応する指摘の下に追記する

## 4. 実行

`npm run test:security`を実行する。`e2e/security.spec.ts`が存在する場合は
`npm run test:e2e:security`も実行する（無ければスキップし、その旨をレポートに書く）。
実行結果（成功/失敗数、失敗したテスト名）をレポートの末尾に追記する。

## 5. 判定と報告

- **全テスト成功**：レポートを完成させ、ユーザーへ完了報告する
- **失敗あり**：失敗したテスト＝脆弱性が顕在化したものとして扱う。該当する指摘の修正案（差分イメージ）
  を提示し、**ここで一旦停止してユーザーの承認を待つ**。本番コードの修正は、ユーザーが承認するまで
  絶対に行わない
  - 承認を得たら、提案どおりに本番コードを修正し（このコマンドを実行している本体セッションが行う。
    `security-reviewer`・`security-test-writer`はどちらも本番コードを編集できない）、
    `npm run test:security`（該当すれば`npm run test:e2e:security`も）を再実行する
  - この「修正→再実行」のループは最大3回までとする。3回で解消しない場合は、状況（何が失敗し続けて
    いるか、試した修正、推測される原因）を報告してループを終了する
  - 再実行のたびにレポートを更新する

## 6. 破壊的操作への注意

依存パッケージの大幅なアップデート（`npm audit fix --force`等、破壊的変更を伴うもの）や、CI設定・
`.gitignore`・GitHub Actionsワークフロー等の一括変更は、指摘の修正案として提示するだけに留め、
**ユーザーの事前承認を得るまで実行しない**。

## 補足

- 攻撃的なE2E入力は、ローカルで起動したアプリ（`npm run dev`または`vite preview`）に対してのみ行う。
  外部サービス・第三者システムには一切送らない
- `security-reviewer`・`security-test-writer`のいずれも設定変更・依存インストール・ネットワーク
  アクセスができないため、それらが必要な作業（gitleaks等新規ツールの導入、Dependabot設定の追加等）は
  本体セッション（このコマンドを実行している自分自身）が、ユーザーへの提案・承認を経てから行うこと
