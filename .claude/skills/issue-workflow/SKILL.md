要望・要件をIssue駆動で開発するときは、以下の手順に従う。詳細な背景・理由づけは
`docs/issue-workflow.md`を参照すること（括弧内は同ドキュメントの節）。

1. **Issue下書き**（3.1）：`.github/ISSUE_TEMPLATE/feature_request.md`の構成（概要／背景・目的／要件／
   対象範囲外／受け入れ条件／参考資料）に沿って内容を埋めた下書きを作成する。
   受け入れ条件は`npm test`等で検証可能な粒度で書く
2. **仕様レビュー**（3.2）：作成した下書きを`issue-spec-reviewer`サブエージェントに渡し、目的・効果の明確さ／
   要件の分解粒度／開発方針との整合性／費用対効果／テンプレート必須項目の充足を確認させ、改善済みの
   下書きを得る。このレビュー後の下書きをチャット上に提示する
3. **承認ゲート**（3.3）：ユーザーの承認を得るまでIssueを起票せず、4以降へも進めない。修正依頼があれば
   下書きに反映し再提示する（軽微な修正であればレビューをやり直さなくてよい）。承認後にIssueを起票する
4. **ブランチ作成**（4）：Issue番号がわかるブランチ名で作業する（Claude Code on the webのセッションでは
   払い出されたブランチをそのまま使う）
5. **開発計画・下書きPR**（5）：方針／変更予定ファイル／タスクのチェックリスト／受け入れ条件の検証方法／
   リスク・未決事項を、`.github/PULL_REQUEST_TEMPLATE.md`の「開発計画」節に書く。
   `git commit --allow-empty`で着手コミットを作ってpushし、先頭に`Closes #<Issue番号>`を書いた
   **下書き（draft）PR**として作成する
6. **計画レビュー**（6）：Issue本文と開発計画を`logic-reviewer`（要件との整合性・合理性）・`ux-reviewer`
   （UI/UX）・`security-reviewer`（安全性・堅牢性）に「計画レビュー」として渡す。明らかに該当しない観点は
   理由を記録して省略してよい。指摘を計画に反映し、PR本文の「計画レビュー結果」に指摘と対応を記録する。
   レビューで決められない論点は実装前にユーザーに確認する
7. **実装・テスト**（7）：計画のタスクに沿って実装し、終わったタスクにチェックを付ける。`CLAUDE.md`の既存ルールを
   踏襲する。仕様の解釈・追加決定が必要な場合は`docs/design.md` §3に追記し、`docs/v5-spec.md`本体は直接編集しない。
   計画を変えたらPR本文の計画を更新し「計画からの変更点」に理由を書く
8. **実装レビュー**（8）：`src/domain/`を変更したら`logic-reviewer`、`src/components/`を変更したら
   `ux-reviewer`でレビューし、`/security-review`を実行する
9. **実装結果の記録・Ready for review**（9）：PR本文の「実装結果」「受け入れ条件の充足」「テスト」「確認事項」を
   埋める（実装結果はコメントではなく本文に書く。各項目は`docs/process/dod.md`のD1〜D8に対応し、
   「人の確認」欄はユーザーが記入するので埋めない）。CI（`test`・`a11y`・`e2e-scenario`）がgreenであることを
   確認してから下書きを解除する
10. **PRレビュー**（10）：`/code-review --comment`で差分を検査し、あわせてPRと実装の整合性／計画タスクの実施／
    受け入れ条件の充足／品質ゲート／確認事項の5観点の確認結果をPRコメントに投稿する。ユーザーも同じ観点で
    レビューする。指摘には修正をpushして返信する
11. **マージ後**（11）：マージはユーザーが行う。Issueが自動クローズされたことを確認し、`CLAUDE.md`
    「現在の実装状況」「次にやるべきこと」の更新要否を判断する

複数のIssueを同時並行で実装するよう依頼された場合は、4（ブランチ作成）に入る前に
`docs/issue-workflow.md` §12の手順に従う：対象Issueのfootprint（影響しそうなファイル）を確認し、
重ならないIssueだけを同時並行にする。並行実行するIssueは、別ブランチ・別セッション（`create_session`）
または別worktreeなど、作業領域を分離すること。
